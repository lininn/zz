# Agent Crew P1 — 外部 Runtime 接入

日期：2026-09-24。沿用 P0 的 crew 命名、成员快照、消息/执行幂等键及全局 workspace 租约。

## 范围与所有者

- 成员 `runtime` 为 `zcode`、`claude-cli`、`codex-cli`、`opencode-cli`；后三者仅经 CLI 的 ExternalRuntimeDispatchService / facade 执行，绝不降级到 ZCode 模型。
- CrewService 持有群板、成员快照及执行状态；外部 dispatch coordinator 持有 vendor attempt、事件与 native session；进程仍由 ExternalRuntimeProcessHost 管理。Host 通过严格校验的窄协议访问 facade，不跨包引用 runtime 实现。
- 外部执行同样取得 CrewWriteAdmission 的全局 workspace 单写租约（含普通会话）；只有确认停止才能释放。未知 ACK / 失联 / 重启保持 recovery_required，不重放已启动任务。
- 续跑只用 `resumeNativeSessionId`，限制在同 group/member/configVersion/epoch/runtime 的成功执行历史；复制、重绑与成员变更不得复用旧上下文。

```text
群板 @成员 → CrewService（原子入队）→ runtime binding preflight
  → 同一 workspace 租约 → Host 窄协议 → CLI facade / dispatch coordinator
  → adapter.start(one-shot, optional resumeNativeSessionId) → vendor process
  → normalized event / terminal result → Crew 群板投影 → 确认停止 → 释放租约
权限请求 → 群板审批 → 拒绝: cancel 并确认停止；批准: 仅使用已实测支持的权限回应
未知审批回应能力 → 明确不可用/失败，不伪造批准或静默提高权限
桌面 continuous 与手机 replayable → 同一 CrewService 投影/命令；不另起 Host。
```

## 能力与失败规则

- binary/version/auth/JSON output/terminal/permission/leaf enforcement 均基于本机 `--help` 与既有 probe。未知能力标为不可用。命令不得携带凭证或隐式全权限开关。
- Codex/OpenCode 使用各自非交互 JSON 事件协议，未知/畸形 vendor 事件产生 warning；没有可靠 terminal 不得成功。interrupt/cancel 走 process host，结构化最终结果必须符合 ExternalRuntimeResult。
- preflight 拒绝发生在输入 admission 之前，成员与群内展示 unavailable 及安全原因；已入队任务能力失效则明确失败，不伪装恢复中的模型任务。
- `permission.requested` 接现有 Crew hook/RPC/群板交互。拒绝语义与 P0 cancel 一致；只可批准匹配当前 attempt 的未决请求。CLI 没有权限回复能力时明确失败，不能假装已批准。

## 验收（先 fixture，禁止真实网络依赖）

1. Claude/Codex/OpenCode fake binary: success、未知/畸形事件、permission、cancel、preflight-fail、restart recovery。
2. runtime binding 路由及拒绝：不可用 provider 不调用 ZCode；显示安全原因；重复输入不重复派工。
3. 成功执行后同纪元同成员可 resume；重绑/复制/配置变化不 resume；中断执行不自动重跑。
4. 权限展示、批准/拒绝、取消竞态与失联的恢复隔离；租约不提前释放。
5. P0 crew 40 个测试不回退。运行根 typecheck/lint/architecture 和新 fixture；CLI 单独 typecheck。

不包含 Agent→Agent / 自动接力 / 独立 worktree。真实模型 smoke 和浏览器 E2E 若未执行须明确报告。

## CLI/Core/Bootstrap 执行契约

- `crew/runtime` 只接收 `{workspace, command}`，沿用共享 `crewRuntimeCommandSchema` / reply schema；workspace identity 与 remoteSessionId 参与入口隔离，CLI 不消费 Host 租约之外的群状态。
- coordinator 是 attempt 状态唯一所有者。`permission.requested` 在流读取期间发布；只有 adapter 实际实现可选 `respondPermission` 时才允许 approve。拒绝通过 cancel；不支持审批回复的批准请求也取消，不伪造 vendor acknowledgement。
- `settled` 仅在当前 dispatch supervision 完成后成立；运行中 cancel 等待该 task 的 finally，不等其他队列任务，也不把取消请求当作停止证明。重启的 running/preflight/awaiting_permission 转 recovery_required，保持 fenced，不自动重放。
- terminal 的 status/runtimeState/summary/nativeSessionId 来自严格校验的结构化结果。既有 SQLite request_json 使用严格校验的 `_crewRuntime` 保留字段，在同一事务保存 summary/settled；旧 request schema 会剥离该元数据，兼容已有行，不新增 migration。facade 的 scoped queue store 只读写本 workspace 的行，不恢复或派发其他 workspace 的任务。
- resumeTaskId 必须指向同 session/runtime/workspace 的成功且已 settled 记录，且有 nativeSessionId；错误历史明确拒绝。新 taskId/attemptId 不复用旧幂等键。
- outerSandboxReady 只能来自受信启动配置，默认 false；没有部署隔离证明返回 unavailable。P1 不引入绕过权限/沙箱的 CLI 参数。

### P1 查询端不取得执行所有权（跨 Host 审查修复）

- Protocol facade 使用 `recoverOnCreate=false`：构造、probe/read 和只读实例关闭不得恢复、保存、取消或 pump durable queue。legacy facade 缺省仍保留创建时 recover。
- 只读实例直接读取 scoped store 的新快照，不将其他 Host 活跃记录缓存为本地 coordinator 状态；无法证明由本实例监督的未完成任务仅投影 recovery_required/settled=false，不回写该投影。
- 首次显式 start（Host 已持有 Crew lease）才激活本地调度；初始化恢复不能重放其他旧 queued，旧未完成记录保持隔离。只读实例的 cancel/permission 不能伪造其他 Host 的停止证明。

```text
Host B probe/read → query-only facade → fresh scoped store read → projection（零写入、零派发）
Host A 原进程 → coordinator / store（唯一执行写入者）
Host B 获得 lease 后显式 start → 一次恢复且禁止旧队列重放 → 本地 dispatch
```

### 同 scope 的 A→B→A 执行交接

- 每次已持 Crew lease 的显式 start，在本地 coordinator 空闲且没有待处理权限时，先在既有串行 mutation 边界内从 scoped durable store 刷新快照，再做禁止旧 queued 重放的恢复/准入。不能以“本实例曾激活过”代替当前持久化状态。
- 本地 active/pump 或未决 permission 存在时禁止替换快照；重复 start 继续读取当前 attempt，不能触发本地任务恢复或丢掉实时权限。
- 此刷新只从显式 start 进入；probe/read 不触发刷新恢复写入。A 完成 taskA、B 完成 taskB、A 再执行 taskC 后，三个结果必须完整持久化。

### 群板输入与既有 dispatch 限长

- 外部运行时沿用 contracts 的 `objective` 8000 字符上限，不扩大既有 API。
- 组合角色/本次用户任务后，按最旧优先移除群板历史直至满足上限；角色与当前任务不做静默截断。
- 仅角色与当前任务就超过上限时，在创建 task/取得租约之前明确失败为 `crew.promptTooLarge`（zh/en 同步），不进入恢复状态、不调用 ZCode。
- `crew_ext_*` 是外部 task 的保留命名空间，普通会话输入不得借用；公开 runtime start 不接受调用者拼接的租约引用，内部入口核验 fencing token。

- Host 会在新 start 前 read 旧任务来验证 resume 候选：activated 但空闲的 facade 必须读取 scoped durable store 的新结果，不等待 start 刷新。仅本实例当前 active attempt 使用实时投影；已 settled 的本地未决权限只能在 durable attempt/state 一致时补入展示，不能用旧快照覆盖持久化结果。read/probe 全程零写入。
